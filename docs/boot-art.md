# Sample boot artwork and customization

The public sample is neutral geometry generated by `tools/boot_art.py`. It uses a one-second introduction and a two-second loop at 30 FPS. Textures are 640×180 and draw into a 1920×540 region on a black 1920×1080 canvas. The decoded loop is about 26.4 MiB at four bytes per pixel.

```sh
python3 -m pip install -r requirements.txt
python3 tools/boot_art.py
```

Inspect `.local/sample-art/preview.png`, `manifest.json`, `bootanimation.zip` and `sample-module.zip`. The sample is deliberately smaller than the reference artwork. It has no personal logo, imported media or identifiers. For your own artwork, provide `part0/*.png` and `part1/*.png` to `--frames`. Every frame must have the same size; the builder scales trim bounds to the display and checks the aspect ratio.

## Android animation module

The generated module contains exactly three entries:

```text
module.prop
system.prop
system/media/bootanimation.zip
```

It sets `ro.feature.bootanim_cust=false`, the reference TCL switch for suppressing the additional manufacturer intro. This is device-specific, not a general Android property. There are no startup scripts or SELinux rules. Install manually through Magisk only after preserving the original animation and confirming the target path/property on your build.

Android's native boot-animation player can decode all loop frames into memory. Budget `width × height × 4 × loop frames`, plus player/graphics overhead. The larger reference was previewed in an isolated mount namespace with temporary properties restored, explicit memory limits and the normal boot-complete exit signal. Its sampled RSS peaked around 527 MiB; this is an observation from that animation, not a forecast for the sample or every TV.

Avoid a native preview that bind-mounts over the running system globally. A preview timeout is not itself a memory failure. Verify the player exits normally and a real reboot finishes before accepting an animation. To undo the sample while Android is functioning, disable/remove module `tv_sample_art` in Magisk and reboot deliberately.

## Early static warning image

This is a separate, more sensitive stage. The reference replaced only `orange_state.raw` in the bootdata filesystem, retaining the unlocked/orange security state. Replacing artwork does not restore verified boot or relock the bootloader.

The observed early format was 1280×720, full-range BT.601 YUYV422, 1,843,200 bytes. To encode an image at its existing dimensions locally:

```sh
python3 tools/boot_art.py --raw-source .local/my-static-image.png
```

The encoder does not resize, install or validate compatibility with a bootloader. Confirm your own raw format, color conversion, resolution, file size and display appearance. A correct byte length alone does not prove compatibility.

Before an early-image write, preserve the full bootdata partition, original RAW, file manifests, permissions, owner, SELinux context, timestamps, vbmeta and trailing verification material. The reference made only the filesystem/block device writable temporarily, staged and hash-checked the replacement, atomically renamed it, synced, and restored read-only protection. Only the intended file changed, with vbmeta bytes unchanged.

There is deliberately no generic raw-partition writer here. Mount layout, verification mode and recovery differ by firmware. A root check plus a matching model name is insufficient. Recoverable rooted-Android artwork changes do not justify blind writes to bootloader code or vbmeta.
